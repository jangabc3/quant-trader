# 설계 문서: 퀀트 자동매매 프로그램 (가칭 QTrader)

작성일: 2026-10-27
대상: 본인 + 각자 PC에 설치해 쓰는 사용자
시장: 국내주식(KOSPI/KOSDAQ) + 미국주식(NASDAQ/NYSE/AMEX)
증권사: 한국투자증권 Open API (KIS) — 실전/모의투자 모두 지원

## 원칙

- **모든 코드는 새로 작성**합니다. 다른 프로그램의 코드·디자인·문구는 쓰지 않습니다.
- **사용자 돈과 키는 사용자 PC에만** 있습니다. 서버가 남의 계좌로 주문하지 않습니다.
- **기본값은 안전 쪽**입니다. 처음 설치하면 내장 가상매매(paper)로 돌고, 실전 주문은 사용자가 직접 두 번 확인해야 켜집니다.

## 스택

| 계층 | 선택 | 이유 |
| --- | --- | --- |
| 언어 | Python 3.11+ | 퀀트 생태계(pandas/numpy)가 가장 두텁다 |
| 데이터 처리 | pandas, numpy | 지표·백테스트 표준 |
| 증권사 연동 | requests + KIS REST | 공식 문서·예제가 있고 윈도우 전용 OCX가 필요 없다 |
| 저장소 | SQLite (표준 라이브러리) | 설치형이라 서버 DB가 필요 없다 |
| 비밀 보관 | keyring (Windows 자격 증명 관리자) | API 키를 파일에 평문으로 두지 않는다 |
| 화면 | FastAPI + 로컬 웹 대시보드 (http://127.0.0.1:8765) | 브라우저만 있으면 되고, 외부에 열리지 않는다 |
| 스케줄 | 내장 스케줄러 (zoneinfo로 서울/뉴욕 시간 계산) | 서머타임을 자동 처리 |
| 배포 | PyInstaller 단일 실행파일 (다음 단계) | 사용자가 파이썬을 몰라도 된다 |

## 핵심 구조

```
데이터(KIS 일봉 / CSV)  ->  전략(목표 비중)  ->  리스크 관리  ->  주문 생성(현재 보유와의 차이)  ->  브로커(paper / KIS 모의 / KIS 실전)
                                                                                     |
                                                                SQLite: 주문·체결·잔고 스냅샷·로그
```

모든 전략은 **"종목별 목표 비중"** 을 돌려줍니다. 그래서 백테스트와 실매매가
같은 코드 경로를 탑니다. 백테스트에서 본 것이 실매매에서 그대로 일어납니다.

## 전략

| 전략 | 규칙 (기본값, 모두 설정 가능) |
| --- | --- |
| 추세추종 `trend` | 단기 이평(20) > 장기 이평(60)이면 보유, 아니면 청산. ATR 기반 변동성 조절 비중 |
| 모멘텀 순위 `momentum` | 최근 N일(120) 수익률 상위 K개(5)를 동일 비중으로 보유, 리밸런싱 주기(20거래일). 절대 모멘텀이 음수면 현금 |
| 평균회귀 `meanrev` | RSI(14) < 30 또는 볼린저 하단 이탈 시 진입, RSI > 55 또는 중심선 회복 시 청산 |

## 리스크 관리 (주문 직전에 항상 통과)

- 종목당 최대 비중 (기본 20%)
- 총 투자 비중 상한 (기본 95%)
- 1회 주문 최대 금액
- 일일 손실 한도 (기본 -3%) 도달 시 **킬 스위치**: 신규 매수 중단
- 허용 종목 목록 밖 종목은 주문 거부
- 같은 날 같은 종목 중복 주문 방지 (재시작해도 SQLite로 확인)

## 데이터 모델 (SQLite)

```
orders     id, ts, account, market, symbol, side, qty, price, order_type, status, broker_order_id, strategy, message
fills      id, order_id, ts, qty, price, fee, tax
positions  account, market, symbol, qty, avg_price, updated_at        (paper 브로커용)
cash       account, currency, amount                                  (paper 브로커용)
equity     ts, account, equity, cash
events     ts, level, source, message                                 (대시보드 로그)
bars       market, symbol, date, open, high, low, close, volume       (일봉 캐시)
```

## 로컬 API (대시보드용, 127.0.0.1 전용)

| 메서드 경로 | 하는 일 |
| --- | --- |
| GET /api/status | 모드, 킬 스위치, 다음 실행 시각, 계좌 요약 |
| GET /api/positions | 보유 종목 |
| GET /api/orders | 최근 주문 |
| GET /api/events | 로그 |
| POST /api/backtest | 전략·종목·기간으로 백테스트, 자산곡선과 지표 반환 |
| POST /api/run-once | 지금 한 번 실행 (dry-run 가능) |
| POST /api/kill-switch | 킬 스위치 켜기/끄기 |
| GET/PUT /api/config | 전략·리스크 설정 |
| PUT /api/secrets | KIS 키 저장 (keyring) |

## 까다로운 부분

- **시간대**: 국내 09:00–15:30 KST, 미국 09:30–16:00 ET. 서머타임은 zoneinfo로 계산.
- **휴장일**: 1차 버전은 주말만 거르고, 휴장일 주문은 증권사가 거부한 것을 기록. 다음 단계에서 KIS 휴장일 API 연동.
- **토큰 한도**: KIS 접근 토큰은 하루 발급 횟수 제한이 있다 → 파일에 캐시해 재사용.
- **API 호출 제한**: 초당 호출 수 제한 → 요청 사이 간격을 둔다.
- **미국 모의투자**: 지정가만 가능 → 미국 주문은 현재가 ±오프셋 지정가로 낸다.
- **중복 실행**: 같은 날 같은 전략이 두 번 돌면 주문이 두 번 나간다 → 실행 기록으로 막는다.

## 규제 메모 (사업화 전 반드시 확인)

- 사용자가 **자기 키로 자기 PC에서** 돌리는 소프트웨어 판매는 투자일임과 구조가 다르다.
- 다만 **매매 신호·종목 추천을 유료로 제공**하면 유사투자자문업 신고 대상일 수 있고,
  남의 계좌를 대신 운용하면 투자일임업 등록이 필요하다. 출시 전 금융 전문 변호사 확인을 권장한다.
- 프로그램과 백테스트 결과는 투자 권유가 아니며, 손실 책임은 사용자에게 있다는 고지를 넣는다.

## 개발 순서

1. **세로 한 줄(vertical slice)**: CSV/합성 데이터 → 전략 → 백테스트 → paper 브로커 주문 → 대시보드 표시
2. KIS 연동: 토큰, 일봉, 잔고, 주문 (모의투자로 검증)
3. 스케줄러 + 킬 스위치 + 중복 방지
4. 설치 파일(PyInstaller), 사용자 설정 마법사
5. 휴장일 API, 텔레그램 알림, 전략 추가
